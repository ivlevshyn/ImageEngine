# Package validation and execution limits

This course package contains Markdown teaching material, not a completed engine. The learner creates source files outside `learning/` as directed. Examples labeled as fragments are intentionally not complete standalone functions.

## Checks performed during preparation

- Verified that all 50 lesson IDs occur exactly once as lesson definitions, in ten modules of five lessons.
- Checked each lesson for an outcome, explanatory material, implementation work, final verification, understanding questions, and completion criteria.
- Checked relative file links and fenced-code balance throughout the package.
- Checked that the ZIP contains only files beneath `learning/`, with no generated project implementation or private build artifacts.
- Reviewed the Apple-specific symbol/calling-convention strategy, register use in complete sample functions, and buffer contracts.
- Independently recalculated the worked integer/color examples and exhaustively checked the stated bounded divide-by-nine identity.
- Checked the integer grayscale neutral-color invariant, blend endpoints, contrast identity, resize index examples, and sRGB byte round-trip/midpoint examples with independent arithmetic scripts.
- Verified that the early supplied C declarations and complete assembly-function names correspond, and that complete assembly samples have explicit return paths.
- Opened the main official reference pages used for platform, language, debugger, SIMD, and image-format guidance. Links are live resources and can move after preparation.

## What these checks do not establish

The authoring environment did not provide Apple's Swift/Clang toolchain, a macOS SDK, or an Apple Silicon runtime. The Markdown examples were therefore **not natively compiled or executed on the learner's Mac** during preparation. The package does not claim native runtime, debugger, performance, or framework-integration validation.

M01 establishes a local build immediately. Every lesson includes its own local correctness checks; framework and concurrency scaffolding must be reconciled with the installed SDK/compiler when taught. If a genuine technical error is discovered, the tutor should explain it, propose the smallest correction, and record it below instead of silently changing course contracts.

No hardware-specific speedup, core count, cache size, or optional instruction extension is assumed from the learner's reported machine model. Benchmarks are learner-generated evidence tied to their implementation revision and environment.
